# DECISIONS.md — журнал решений

Правила ведения (договорились на старте, см. README):
- одно решение = один блок `D-NNN`; нумерация не переиспользуется;
- статусы: `принято`, `принято (ожидает подтверждения ...)`, `отменено (см. D-XXX)`;
- сюда пишем и **открытые вопросы**, чтобы контекст жил в репозитории, а не в чате.

---

## Принятые решения

### D-001. Репозиторий и venv — внутри `Smena/`
Принято: 2026-11-08.
Пустой `.git` и пустой `venv`, случайно созданные в родительской папке `codesss/proj`,
удалены (коммитов не было — потерь нет). `git init` и `.venv` выполнены в `Smena/`.
Ветка по умолчанию — `main`. Имя `.venv` (с точкой), чтобы не путать с будущими окружениями
и чтобы `.gitignore` его гарантированно накрывал.

### D-002. Конфигурация через переменные окружения, без pydantic-settings
Принято: 2026-11-08.
`app/config.py` читает env; для локальной разработки поддерживается файл `.env`
(простейший парсер в самом модуле, переменные окружения имеют приоритет над файлом).
На VPS источник — `Environment=` в systemd unit. pydantic-settings не вводим:
зависимости держим минимальными (в стеке ТЗ его нет). `.env` в `.gitignore`,
шаблон — `.env.example`.

### D-003. PRAGMA SQLite задаются на каждом подключении
Принято: 2026-11-08.
`journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=5000`, `foreign_keys=ON`
устанавливаются обработчиком события `connect` (файл `app/db.py`) — иначе WAL/лимайты
не применялись бы к новым соединениям пула. `BEGIN IMMEDIATE` — helper
`immediate_transaction()`; сервисные функции на T05+ обязаны писать изменения
только через него (единственный воркер uvicorn это допускает, ТЗ требует именно так).

### D-004. Фабрика приложения `create_app(settings)`
Принято: 2026-11-08.
Нужна pytest с временной БД: каждый тест строит приложение со своими настройками.
`app = create_app()` остаётся на уровне модуля для `uvicorn app.main:app`.

### D-005. Публичные OpenAPI-схемы отключены
Принято: 2026-11-08.
`docs_url=None`, `redoc_url=None` — публичного API у продукта нет, только формы;
схема упрощала бы разведку атакующему. Для разработки схемы не нужны (маршруты читаются в коде).

### D-006. Служебный маршрут `GET /health`
Принято: 2026-11-08.
Возвращает `{"status":"ok"}` без обращения к БД; используется для проверок
живости (Caddy `request timeout 10 с`, systemd-скрипты, будущий мониторинг).

## Открытые вопросы (не блокируют старт)

### Q-001. A-3 — круг принимающих смену
Статус: **ожидает подтверждения Лошманова (Участник 1)**.
Текущая реализация по ТЗ v1.1.2: принять смену может любой активный ADMIN, кроме сдавшего
(отклонение от бизнес-гипотезы). При смене ответа правим сервис приёма + тест AC-7.

### Q-002. GET-403 (FORBIDDEN на GET-маршруты)
Статус: принято временное решение.
Рендерим по таблице ошибок ТЗ (страница ошибки с кодом/описанием), без редиректа на вход.
Подтвердить у Сотникова при удобном случае.

### Q-003. T15 (S-пункт, 3 ч резерв)
Статус: **вне критического пути, первый кандидат на отсечение** при отставании от графика.
Отсечение зафиксировать здесь отдельным D-блоком.

### Q-004. Прототипы-макеты
Статус: принято.
Макеты местами несогласованы по мокап-данным — кодируем строго по тексту FR,
не по картинкам (решение действует на все задачи UI).
