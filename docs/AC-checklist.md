# Чек-лист приёмки T14 (AC-1 … AC-13)

Как пользоваться: прогонять на развёрнутом стенде (VPS по HTTPS). Для каждого
пункта — дата, «ок/не ок», кто проверял; скриншоты складывать в `docs/accept/`
(не коммитить в git без нужды). Ручные сценарии: AC-1, AC-9, AC-12, AC-13
(остальное покрыто автотестами `pytest`, здесь повторяется вживую).

Подготовка: `python scripts/seed_demo.py` (или регистрация чистого отеля).
Логины seed: demo-manager / demo-anna / demo-ivan, пароль `demo-pass-123`.

## AC-1 — основной цикл двумя учётными записями
- [ ] Анна: открыть смену, 2 вопроса (один решён), сдать смену.
- [ ] Анна: журнал показывает «Ожидает приёма», своей передачи нет.
- [ ] Иван: в журнале карточка ожидающей передачи → снимок → «Принять смену».
- [ ] Flash «Смена принята, перенесено 1 вопрос»; вопрос тот же id у Ивана,
      решённый остался у Анны; в карточке — CARRIED.
- [ ] Анна правит свой решённый/чужой вопрос → SHIFT_NOT_EDITABLE (flash).

## AC-2 — повторы и параллельность (автотесты test_boundary_t08)
- [ ] Два быстрых клика «Сдать смену» (F12: отключить JS-блокировку) — одна
      передача, снимок один.
- [ ] Два окна (Иван, Пётр) жмут «Принять» одновременно — один принял,
      второй: «Смена уже принята: …, ALREADY_ACCEPTED».
- [ ] Тот же Иван повторно — «Вы уже приняли эту смену».

## AC-3 — до приёма (PENDING)
- [ ] Смена в статусе «Ожидает приёма»; вопрос сданной смены не правится и
      не закрывается (SHIFT_NOT_EDITABLE); передача видна в журнале другому
      ADMIN и в обзоре MANAGER.

## AC-4 — уточнение после приёма
- [ ] Иван правит перенесённый вопрос → EDITED в его смене; в снимке передачи
      текст прежний.

## AC-5 — закрытие и история
- [ ] Закрытый вопрос не переносится, виден в «История → вопросы» и в карточке
      (автор, изменения, переносы, закрытие).

## AC-6 — изоляция отелей (второй отель в приватном окне)
- [ ] Прямые адреса /issues/{id}, /handovers/{id}, /shifts/{id}/handover
      чужого отеля → «Страница не найдена» (GET 404) / 303+NOT_FOUND (POST).

## AC-7 — роли
- [ ] ADMIN: /overview, /history, /staff → 403 «Это действие вам недоступно».
- [ ] MANAGER: /journal → 403; POST «Открыть смену»/«Сдать»/«Принять» → 303+FORBIDDEN.
- [ ] Автор не принимает свою передачу (кнопки нет; POST → FORBIDDEN, состояние не изменилось).

## AC-8 — поиск
- [ ] /history: «кух» находит «Кухня» (регистр и «ё» не важны); «вёс» находит «весь».
- [ ] date_from=date_to=сегодня включает события текущего местного дня.

## AC-9 — восстановление из копии (РУЧНАЯ, на тестовой базе!)
- [ ] scripts/backup.sh → копия появилась в внешнем хранилище (rclone ls).
- [ ] scripts/restore.sh <копия> на тестовом стенде → данные целы, приложение
      работает (см. scripts/README-backup.md).

## AC-10 — сбой записи (автотест)
- [ ] Повторять вживую не обязательно; при желании: снять у файла БД права на
      запись (chmod 444 у файла и каталога) и создать вопрос → страница
      «Запись не сохранена» (500), в базе пусто; затем вернуть права.

## AC-11 — лимит 10 записей (автотест)
- [ ] В живую: создать 10 сотрудников, 11-й → «Достигнут лимит: 10 учётных
      записей на отель».

## AC-12 — 15 минут (РУЧНАЯ, секундомер, человек без контекста проекта)
- [ ] Регистрация отеля → 2 сотрудника → «Создать демо-передачу» → вход под
      ADMIN → приём демо. Время ≤ 15 минут, без подсказок.

## AC-13 — безопасность и мобильный экран (РУЧНАЯ часть + автотесты)
- [ ] SQLite: SELECT password_hash — только argon2-хеши.
- [ ] http:// → 301 на https; замок в браузере.
- [ ] DevTools→Cookies: HttpOnly, Secure, SameSite=Lax у smena_session.
- [ ] POST без csrf_token (curl) → страница «Страница устарела… CSRF_FAILED».
- [ ] Все экраны при ширине 360 px (DevTools device toolbar): без горизонтальной
      прокрутки, кнопки ≥44 px: login, register, journal, issue form, issue card,
      handover check, snapshot, overview, history, staff, error.
